# InfraMap — Domain Context & Ubiquitous Language

> **Shared Domain Vocabulary**: This document establishes the ubiquitous language used across all code, tests, and documentation within the InfraMap codebase.

## Core Domain Terms

| Term | Definition | Code Representation |
|---|---|---|
| **InfraMap** | Open-source network infrastructure discovery, mapping, and observability platform. | Repository root (`github.com/matheussouza/inframap`) |
| **Node** | Physical, virtual, or cloud infrastructure entity (e.g., Server, Switch, Router, VM, Container). | `Table: nodes`, `struct Node` |
| **Interface** | Physical or logical network interface attached to a Node (e.g., eth0, vlan10). | `Table: interfaces`, `struct Interface` |
| **Link** | Point-to-point connection between two interfaces on separate nodes. | `Table: links`, `struct Link` |
| **Topology** | Graph representation of Nodes, Interfaces, and Links forming the network map. | Domain package: `internal/domain/topology` |
| **Discovery Engine** | Subsystem responsible for scanning IP ranges, executing plugins, and ingesting assets. | Domain package: `internal/domain/discovery` |
| **Discovery Source** | Configuration targeting a range, subnet, or provider API for automated discovery. A source acts as a Discovery Plan grouping one or more Source Collectors. | `Table: discovery_sources` |
| **Source Collector** | Individual discovery method (ICMP, ARP, mDNS, Proxmox, Docker, UniFi) attached to a Discovery Source. Each collector has its own config and runs independently. | `Table: discovery_source_collectors` |
| **Collector Run** | Timestamped execution record of a single collector within a Discovery Source run, capturing status, duration, devices found, and error details. | `Table: discovery_collector_runs` |
| **Discovery Record** | Timestamped raw observation output produced by a discovery scan. | `Table: device_discovery_records` |
| **Partial Status** | Discovery Source execution outcome when some collectors succeed and others fail. Distinct from `error` (all failed) and `success` (all succeeded). | `discovery_sources.last_status = 'partial'` |
| **Credential** | Encrypted authentication secret used by discovery collectors (SNMP, SSH, API token). | `Table: credentials` |
| **System State** | Singleton configuration entity tracking installation status, telemetry, and technical metadata. | `Table: system_state`, `struct SystemState` |
| **Onboarding** | Single-shot system initialization process creating instance ID, system roles, and initial admin user. | `modules/configuration/usecase` |
| **System Role** | Built-in RBAC role (`admin`, `operator`, `viewer`) seeded during system onboarding. | `Table: roles`, `struct Role` |
| **Session Token** | Cryptographically secure stateful token prefixed with `ims_` used for authentication. | `Table: user_sessions`, `struct UserSession` |
| **Sliding Session** | Session model with 30-minute inactivity sliding renewal managed by `SessionRepository` and 7-day hard absolute expiration limit. | `modules/identity/repository` |
| **Auth Context** | Request context carrying authenticated `userID` and assigned RBAC `permissions` list. | `internal/platform/httputil` |
| **Discovery Collector** | Plug-and-play worker (ICMP, ARP, Reverse DNS, SNMP) gathering raw network facts. | `modules/discovery/collectors` |
| **Credential Set** | Priority-ordered set of vault credentials linked to a Discovery Source for automated auth. | `modules/credentials` |
| **Validator Phase** | Discovery pipeline stage enforcing MAC, IP, and hostname sanity constraints before matching. | `modules/discovery/engine/validator.go` |
| **Inventory Sync** | Database persistence phase applying reconciled asset updates and triggering domain events. | `modules/discovery/engine/inventory_sync.go` |
| **Device Inventory** | System of record for all physical, virtual, and network devices. | `modules/inventory`, `Table: devices` |
| **Device Staging** | Holding queue for newly discovered devices awaiting manual verification before promotion to active inventory. | `modules/inventory`, `Table: device_staging` |
| **User-Locked Fields** | Device properties modified manually by an operator, protected from automated scanner overwrites. | `metadata->'user_locked_fields'` |
| **Field Confidence Scores** | Per-attribute confidence scores (`metadata->'field_confidence_scores'`) governing reconciliation precedence. | `modules/discovery/engine` |
| **Discovery Scheduler** | Background service that executes discovery scans on cron schedules defined per Discovery Source. Manages one job per source with in-memory concurrency control. | `modules/discovery/scheduler` |
| **Reconciliation Loop** | Periodic (5 min) consistency check comparing registered scheduler jobs against database state, correcting drift independently of event bus reliability. | `modules/discovery/scheduler` |
| **Scan Concurrency Lock** | In-memory per-source mutex preventing concurrent scan execution of the same Discovery Source. Single-instance only; designed for future evolution to distributed advisory locks. | `modules/discovery/scheduler` |
| **Onboarding Coordinator** | Singleton that sequences the Product Tour and Setup Wizard overlays, ensuring mutual exclusion and logical ordering (Wizard first, then Tour). Reads existing LocalStorage keys without introducing new persistence. | `frontend/ui/onboarding/OnboardingCoordinator` |
| **Auto Network Setup** | Zero-friction inline Dashboard flow that auto-detects server network interfaces and offers one-click subnet + discovery source creation + first scan. Coexists with the manual Setup Wizard. | `frontend/ui/dashboard` |
| **Collapsible NavRail** | Dual-state sidebar navigation: expanded (~200dp, icon + label) by default for new users; collapses to 56dp icon-only via toggle. State persisted in LocalStorage. | `frontend/designsystem/NavRail` |

## Mandatory Engineering Guidelines (Learned from Code Reviews)

Guidelines below are continuously updated from internal code reviews, CodeRabbit findings, and peer audits.

1. **Opaque Error Responses in Controllers**: HTTP handlers MUST return generic, opaque messages to clients (e.g. `"Failed to process request"`) and log root cause details internally (`log.Printf` / `slog.Error`).
2. **Clean Concurrency & Graceful Shutdown**: Background workers MUST take `context.Context` for clean termination. Async event bus tests MUST use a buffered `chan string` + `select`/`time.After(5s)` for synchronization — never unbounded `sync.WaitGroup.Wait()` or `time.Sleep`.
3. **Pure Validation & Explicit Normalization**: DTOs MUST separate mutating `Normalize()` (trimming, default values) from pure `Validate()` methods. Input range checks (e.g., `0..100`, valid IP/CIDR/MAC) MUST be executed before domain logic.
4. **Sanitized Logging & Sentinel Errors**: Dynamic user data in log strings MUST be sanitized (`sanitizeLogInput`). Error wrapping MUST preserve sentinels (`fmt.Errorf("%w: %v", SentinelErr, err)`) for `errors.Is` compatibility.
5. **No Error Swallowing & Mandatory Logging**: All error returns and parse failures MUST be either returned to caller or logged via `slog.Warn/Error`.
6. **Paginated Database Queries**: Any database listing operation used for in-memory matching/processing MUST use pagination loops to handle datasets > 1000 items.
7. **Resilient JSON Type Assertions**: Dynamic JSON metadata unmarshaled into `map[string]interface{}` MUST handle numbers (`float64`) and strings via `fmt.Sprintf("%v", val)`.
8. **Strict Encryption Enforcement**: Operations requiring secret storage MUST error when encryptors are missing, with NO silent fallback to plaintext.
9. **Module-Local Sentinel Errors**: Modules MUST NOT import sentinel errors (`ErrInvalidUUID`, `ErrInvalidInput`, etc.) from sibling module `usecase` packages. Shared error types belong in `internal/platform/` or are re-declared locally within each module that needs them.
10. **Bootstrap Validation Before Resource Allocation**: Configuration validations (encryptor keys, credentials, feature flags) MUST be performed BEFORE allocating resources that require explicit cleanup (database pools, event bus workers). This prevents resource leaks on validation failures.
11. **SQL Delete Rows Affected Check (`:execrows`)**: SQL delete queries targeting single entities MUST use `:execrows` in `queries/*.sql` and inspect `rowsAffected`. If `rowsAffected == 0`, the repository MUST return `ErrNotFound` (allowing HTTP 404 response).
12. **RFC Spec & DTO Alignment**: RFC endpoint specifications MUST match 1:1 with the actual JSON structure returned by DTO structs (preventing discrepancies between documentation and code).
13. **Strict TLS Protocol Configuration (`MinVersion`)**: Any `tls.Config` constructed for HTTP clients or TLS listeners MUST explicitly specify `MinVersion: tls.VersionTLS12` (or `tls.VersionTLS13`) to prevent TLS fallback security warnings.
14. **URL Scheme & Host Validation for External Requests**: Any user-provided URL string used to construct `http.Client` requests MUST be parsed via `url.Parse` and validated to enforce explicit allowed schemes (`http://` or `https://`) and a non-empty host before request execution, preventing SSRF / uncontrolled data in network request vulnerabilities.
15. **Ordering Subscription & Replay Query in Event Streams**: Streaming HTTP handlers (such as SSE) MUST register client subscription (`Subscribe()`) BEFORE executing past event replay queries (`GetEventsAfter(lastEventID)`). This eliminates race windows where live events emitted during the replay query phase could be dropped.
16. **Non-Blocking Event Drop Visibility & Safe UUID Construction**: Event message builders MUST handle UUID generation without calling `uuid.Must` (avoiding panic in background EventBus workers). Channel broadcast drops in event gateways MUST log a warning (`slog.Warn`) with event metadata.
17. **Deterministic Async Test Synchronization**: Unit tests waiting for background goroutines or channel subscriptions MUST use deterministic state polling (e.g. `waitForSubscriber(gw, count, timeout)`) instead of arbitrary fixed `time.Sleep` durations to prevent test flakiness under CI load.
18. **Explicit HTTP Client Timeout for External Requests**: Any `http.Client` created for external API calls (provider integrations, webhooks, health checks) MUST set an explicit `Timeout` field (e.g. `30 * time.Second`). Omitting it causes the client to hang indefinitely if the target accepts the TCP connection but never responds.
19. **Error Logging in Non-Critical Provider Fetch Paths**: Provider integration code that fetches optional or per-item data (e.g., Docker `/info`, Proxmox QEMU VMs per node) MUST log errors via `slog.Warn` before continuing. Silent error swallowing hides operational failures that produce incomplete discovery results.
20. **SSE/Streaming Write Error Handling**: Every write to an SSE `http.ResponseWriter` (`fmt.Fprint`) MUST check the returned error. On failure, log via `slog.Error` and return immediately — `defer unsub()` handles subscriber cleanup. Ignoring write errors keeps dead subscribers registered in the EventBus, filling channel buffers and potentially blocking publishers.
21. **No Hardcoded Cryptographic Keys**: Bootstrap or factory code MUST NEVER use hardcoded, publicly known keys as fallback when environment variables are missing. For development mode, generate an ephemeral random key via `crypto/rand` and log a prominent warning that encrypted data won't survive restarts. Hardcoded keys in source code are equivalent to plaintext storage.
22. **Request Body Size Limits for Secret-Bearing Endpoints**: Controllers that accept secret payloads (credentials, API tokens, SSH keys) MUST apply `http.MaxBytesReader` before decoding. Return HTTP 413 with `errors.As(err, &http.MaxBytesError{})` when the limit is exceeded. This prevents memory exhaustion during JSON decoding and encryption of arbitrarily large payloads.
23. **Database CHECK Constraints for Domain Enums**: When a column represents a closed set of values validated at the DTO layer (e.g., credential types, device statuses), the migration MUST also enforce the constraint via SQL `CHECK (col IN (...))`. This prevents invalid data from bypassing the application layer via direct SQL writes, migrations, or admin tools.
24. **Deterministic Pagination Ordering**: `ORDER BY` clauses in paginated SQL queries MUST include a unique column (typically `id`) as a tiebreaker after the primary sort column. Without it, rows with identical sort values can shift between pages, causing duplicates or omissions.
25. **Gradle/KGP Version Compatibility**: When configuring Kotlin Multiplatform projects, the Gradle wrapper version MUST fall within the Kotlin Gradle Plugin's supported range (e.g., KGP 2.1.21 supports up to Gradle 8.12.1). Using unsupported versions causes build failures or undefined behavior.
26. **Explicit Readiness Signaling for WASM Applications**: Compose/WASM entry points MUST signal readiness to the host page via an explicit callback (`@JsFun` interop calling a JavaScript function). The splash/loading screen MUST transition to an error state with a retry button on timeout, not silently hide.
27. **Unit Tests Must Assert Production Values**: Unit tests MUST compare expected values against actual production constants/functions (e.g., `InfraMapColorScheme.primary`), not hardcoded literal-vs-literal comparisons. Production values referenced in tests MUST be `internal` visibility to enable test access.
28. **CodeQL Language Matrix for Non-JVM Kotlin**: CodeQL workflows with `java-kotlin` in the language matrix MUST exclude Kotlin/WASM and Kotlin/JS source sets from source detection, as the CodeQL extractor only supports JVM-targeted Kotlin.
29. **URL Path Sanitization for File Serving**: Code serving files from `fs.FS` based on URL paths MUST use `filepath.Clean` (not `path.Clean`) for sanitization, followed by `filepath.ToSlash` to maintain forward-slash compatibility with `fs.FS`. Semgrep flags `path.Clean` on user input as `filepath-clean-misuse`.
30. **External Coverage Tool Consistency**: When using external coverage tools (Codecov) as merge gates with multiple CI jobs uploading coverage, configure `after_n_builds: N` (N = number of upload jobs) and `wait_for_ci: true` to prevent premature evaluation. The tool may post a SUCCESS CheckRun after partial data, then correct to FAILURE — but auto-merge already triggered.
31. **Required Status Checks Completeness**: Every CI quality gate job MUST be added to the branch protection required status checks list. A job that runs and fails but is not required will NOT block the merge. Verify with `gh api repos/{owner}/{repo}/branches/{branch}/protection/required_status_checks`.
32. **GITHUB_TOKEN Workflow Trigger Limitation**: `GITHUB_TOKEN` pushes (including auto-merge) do NOT trigger subsequent workflow runs on the target branch. Workflows that must fire on merge (e.g., Release Pipeline) MUST use `pull_request: types: [closed]` with an `if: github.event.pull_request.merged == true` guard instead of `push:` triggers. CI workflows MUST include `workflow_dispatch` for manual baseline refresh. Coverage tools using `target: auto` will have stale baselines without this. See also #100.
33. **Pagination/Normalization Tests Must Assert Normalized Values**: Tests exercising pagination defaults (zero/negative page, out-of-range perPage) MUST assert the actual normalized values passed to the repository mock — not just `err == nil`. Capture limit/offset/status via mock fields and verify against expected defaults.
34. **Concurrent Async API Batching in ViewModels**: When fetching multiple independent API endpoints for a screen/dashboard, ViewModels MUST execute requests concurrently using `coroutineScope` + `async { ... }` instead of sequential `await`s to minimize total network latency. Always cancel any in-flight fetch job before launching a new fetch to prevent stale async responses from overwriting updated state.
35. **Lifecycle Disposal & Cleanup for ViewModels in Compose**: When a Composable instantiates or remembers a ViewModel with background coroutines/jobs (such as auto-refresh loops or SSE event listeners), use `DisposableEffect(viewModel)` with `onDispose { viewModel.clear() }` to guarantee that background jobs are cancelled when the route unmounts or dependencies change.
36. **Codecov Exclusions for Composable UI Screens**: When creating or modifying Compose UI screen files (`*Screen.kt` / `ui/app/**`), ensure they are covered by the `frontend/src/commonMain/kotlin/**/ui/**/*Screen.kt` pattern in `codecov.yml` to mirror Kover exclusions in `build.gradle.kts` and prevent Codecov patch coverage merge blocks on UI layout composables.
37. **Test Scheduler Determinism with Recurring Delay Loops**: In unit tests exercising ViewModels or classes with recurring delay loops (such as periodic auto-refresh), use `runCurrent()` (or explicit time steps with `advanceTimeBy()`) before calling disposal methods (`clear()`, `stopAutoRefresh()`) instead of `advanceUntilIdle()`. Calling `advanceUntilIdle()` while a recurring delay loop is active causes the test scheduler to execute infinite virtual time iterations or throw `UncompletedCoroutinesError`.
38. **SSE Disconnection Handling & Reconnection Loop**: Front-end SSE clients and ViewModels MUST explicitly handle `SSEEvent.Disconnected`. Upon receiving a disconnect event or connection error, close the existing native connection resource (`disconnect()`) and execute reconnection logic with backoff delay (e.g. 5s) inside a controlled loop (`while (isActive)`), preserving `last_event_id` to avoid duplicating event listeners or losing event streams.
39. **Local Pre-Push Quality Gate Enforcement**: The repository configures `.githooks/pre-push` via `make setup-hooks` (`git config core.hooksPath .githooks`). The hook MUST run `make verify` (executing backend Go lint/test + frontend Kotlin `./gradlew jvmTest ktlintCheck detekt koverVerify`). This enforces 85%+ coverage thresholds locally on every `git push`, blocking pushes that would break Codecov or CI gates.
40. **Explicit Reconnection Verification in SSE/Event Stream Unit Tests**: Unit tests exercising event stream handlers (such as `SSEClient` or `WebSocketClient`) MUST track total connection attempts (`connectCount`) in test doubles (`FakeSSEClient`) and explicitly assert that reconnect attempts occur after disconnected events and backoff delays (`assertEquals(2, fakeSse.connectCount)`).
41. **Test Scheduler Execution Guard for Recurring Infinite Loops**: Unit tests exercising ViewModels or background services with infinite recurring loops (`while(isActive) { delay(...) }`) MUST NOT invoke `advanceUntilIdle()` while the loop is active. Use `runCurrent()` to advance scheduled tasks deterministically before stopping background jobs (`stopAutoRefresh()`), avoiding infinite test scheduler execution.
42. **Unified Single-Job Cancellation for Event-Driven Reloads**: When ViewModels reload state in response to asynchronous push events (such as SSE or WebSocket notifications), the reload operation MUST delegate to a single-job runner (`triggerFetchMetrics()`) that cancels any in-flight fetch job (`fetchMetricsJob?.cancel()`) prior to starting a new request. This prevents race conditions where an older, delayed network response overwrites newer data.
43. **Mutation Job Tracking & Reentrancy Guards in ViewModels**: User-triggered MVI mutation actions in ViewModels (such as `createDevice()`, `updateDevice()`, `deleteDevice()`) MUST track their coroutine in a dedicated `Job` variable (e.g., `submitJob`, `deleteJob`), enforce reentrancy guards by checking execution state flags (`isSubmitting` / `isDeleting`), and explicitly cancel all tracked jobs inside the `clear()` method invoked by Compose `onDispose`.
44. **Server-Side Search Parameter Integration in List ViewModels**: Text filter inputs in list ViewModels MUST include the query parameter (`search`) in the HTTP request to the backend API and reset pagination to page 1 (`loadDevices(page = 1)`) on every query change, ensuring searches query the complete dataset.
45. **Isolated Error State Fields for Modal Dialog Actions**: Secondary mutation operations in ViewModels (such as device deletion via a confirm dialog) MUST not write failures to the main list `errorMessage` state. They MUST use dedicated error fields (e.g., `deleteErrorMessage`) so that main list/table contents remain visible while displaying errors in the modal dialog.
46. **Action Contracts Completeness for Feedback Toasts & Modals**: ViewModels supporting transient UI notifications or error dismissals MUST declare explicit action callbacks (`onDismissToast`, `onDismissDeleteError`) in their Action contract data classes (`DeviceListActions`) and wire them to Composable UI listeners.
47. **User-Facing UI Notification Language Standardization**: User-facing notification messages, toast feedback, and error texts emitted by ViewModels or composable components MUST be written in Portuguese (pt-BR) to guarantee visual and linguistic consistency across the InfraMap user interface.
48. **Coroutine Scope Cleanup in ViewModel Unit Tests**: Every ViewModel unit test suite (`DeviceDetailViewModelTest`, `StagingViewModelTest`, `SubnetsViewModelTest`, `CreateSubnetViewModelTest`) MUST invoke `vm.clear()` at the end of each `@Test` method to explicitly cancel all active coroutine jobs (`fetchJob`, `deleteJob`, `submitJob`), preventing `UncompletedCoroutinesError` in headless CI runners.
49. **PR Review Thread Resolution in Merge Automation**: When automation or PR monitoring loops merge a PR via GitHub CLI or GraphQL, unresolved review threads block the `mergePullRequest` mutation. The process MUST inspect review threads via GraphQL (`reviewThreads`), implement code fixes, and explicitly resolve each thread via `resolveReviewThread` before finalizing the merge.
50. **Compose Multiplatform Resources Positional String Placeholders**: In Compose Multiplatform (`compose.components.resources`), XML string resources in `strings.xml` MUST use positional format specifiers (e.g. `%1$s`, `%2$d`) instead of unpositioned placeholders (`%s`). Unpositioned specifiers cause string formatting substitution to fail or render unparsed format strings on non-JVM target platforms.
51. **Navigation Guard in Paginated Base List ViewModels**: Navigation methods in `BaseListViewModel` (`refresh()`, `nextPage()`, `previousPage()`) MUST check `if (currentState.isLoading) return` prior to delegating to `loadPage()`. This prevents duplicate or concurrent page requests from rapid user taps during in-flight network requests.
52. **Job Lifecycle Cleanup in Base ViewModels**: Coroutine job tracking maps in `BaseViewModel` (`launchJob(key)`) MUST register a completion handler (`job.invokeOnCompletion { if (jobs[key] == job) jobs.remove(key) }`) to remove finished jobs upon completion, preventing memory leaks in ViewModels with dynamic job keys.
53. **Streamlined ApiResult Domain Mapping Extension**: Data repositories mapping `ApiResult<DTO>` to `ApiResult<DomainModel>` MUST use `ApiResult<T>.map(transform: (T) -> R)` extension function instead of repetitive `when(result)` branching.
54. **IPv4 Octet Boundary Validation in Domain UseCases**: Subnet and network domain UseCases validating IPv4 CIDRs MUST explicitly verify that each IPv4 octet is an integer within `0..255` (`octet.toIntOrNull() in 0..255`) and prefix mask is within `0..32`, preventing invalid IP strings like `999.168.1.0/24` from passing regex-only checks.
55. **Automated Code Review & Sequential Architectural PR Strategy**: Complex architectural refactorings MUST be split into small, focused, sequential feature branches (Foundation, Domain Layer, Dependency Injection, ViewModel Migration, Version Catalog). Every branch MUST undergo an automated Senior Code Review before opening a PR, enforcing clean architecture boundaries and zero-warning build quality gates.
56. **Gradle Version Catalog Centralization & Dependency Update Auditing**: All Gradle plugins, Multiplatform library artifacts, and version definitions MUST be managed in `frontend/gradle/libs.versions.toml`. Build scripts (`build.gradle.kts`) MUST reference dependencies using type-safe catalog accessors (`libs...` and `alias(libs.plugins...)`). The `com.github.ben-manes.versions` plugin MUST be configured with a stability filter function (`rejectVersionIf { isNonStable(candidate.version) }`) to enable clean dependency update reports via `./gradlew dependencyUpdates`.
57. **Demand-Agnostic Core Documentation**: Official project documentation (RFCs, ADRs, `CONTEXT.md`) MUST be demand-agnostic. They MUST NOT reference temporary scratch folders (`.scratch/`), task ticket IDs (e.g. `T14`, `T15`), or ephemeral task paths. Task-specific execution context and checklists belong exclusively in `.scratch/`.
58. **CoroutineScope Injection Pattern for ViewModel Testability**: All ViewModels MUST accept an optional `scope: CoroutineScope? = null` as their last constructor parameter, forwarded to `BaseViewModel`/`BaseListViewModel`. Production Koin factories omit the parameter (VM creates its own `SupervisorJob` scope). Unit tests pass `scope = this` inside `runTest {}` blocks so the test scheduler controls coroutine execution. The `ownsScope` flag in `BaseViewModel` ensures `clear()` only cancels the scope when the VM created it, preventing `JobCancellationException` when tests inject their scope.
59. **Frontend Three-Layer Clean Architecture Enforcement**: Frontend code MUST follow a strict three-layer architecture: Data (DTOs, API client, repository implementations), Domain (models, repository interfaces, UseCases), and Presentation (ViewModels, Contracts, Screens). Dependencies flow inward: Presentation → Domain ← Data. The Domain layer MUST have zero framework dependencies (no Ktor, no Compose, no Koin annotations). Violations are caught by `KoinModuleCheckTest` and import analysis.
60. **UseCase-Mediated ViewModel Dependencies**: ViewModels MUST NOT depend directly on Repository interfaces. All data access MUST be mediated through single-responsibility UseCase classes injected via Koin. This ensures business logic is testable independently of the presentation layer and prevents ViewModels from accumulating repository-level concerns.
61. **Koin Factory Optional Dependencies via `getOrNull()`**: Koin factory definitions for ViewModels with optional dependencies (e.g., `SSEClient?`) MUST resolve them via `getOrNull<T>()` inside the factory block, not via `parametersOf()` injection. This ensures `koinInject()` at the call site works without parameters. Required parameters (e.g., `deviceId: String`) continue using `parametersOf()`.
62. **Job Cancellation Must Match `launchJob()` Key**: When cancelling background jobs registered via `launchJob("key_name")`, the cancellation MUST use `cancelJob("key_name")` with the matching key. Storing the result of `launchJob()` in a separate `Job?` field and cancelling the field is incorrect — `launchJob` tracks jobs internally by key, so the field is never assigned.
63. **loadPage Override Must Forward perPage Parameter**: Subclasses overriding `BaseListViewModel.loadPage(page, perPage)` MUST forward the `perPage` parameter to the UseCase/repository call. Hardcoding a literal (e.g., `perPage = 50`) silently discards the contract-defined value and breaks any caller passing a different page size.
64. **Server-Side Search Eliminates Client-Side Filtering**: When a list endpoint supports server-side `search` query parameters, the corresponding Screen composable MUST display `state.items` directly. Applying an additional client-side filter causes pagination count mismatches — items matching by non-filtered fields (IP, MAC) are included in the server total but excluded from the displayed table.
65. **Authentication Error Responses Use Localized Resources Only**: Authentication error handlers (login, onboarding) MUST always return `UiText.Resource(Res.string.*)` for user-facing error messages, never `mapError()` which exposes raw backend strings. Backend error details may be logged for debugging but MUST NOT be displayed to the user. This prevents information leakage and ensures consistent UX.
66. **Concurrent API Error Routing Must Identify Actual Failing Result**: When multiple API calls execute concurrently (e.g., Dashboard metrics), the error handler MUST identify which specific result contains the error via `results.firstOrNull { it is ApiResult.NetworkError }` and pass that result to `mapError()`. Passing an arbitrary result (e.g., always `devicesResult`) produces incorrect error messages when a different call failed.
67. **Turbine Mandatory for Flow and StateFlow Testing**: All ViewModel test assertions on `StateFlow` emissions MUST use Turbine's `.test { awaitItem() }` API instead of `async { flow.first { predicate } }` + `advanceUntilIdle()`. Effect assertions on `SharedFlow` MUST use `vm.effects.test { awaitItem() }`. Turbine provides automatic timeout protection and structured flow testing semantics.
68. **Shared Fake Classes Mandatory for Repository Test Doubles**: All ViewModel tests MUST use shared `FakeXxxRepository` classes from `commonTest/.../fakes/` instead of inline anonymous `object : Repository { ... }` stubs. Fakes use `var` result properties for configurable returns and optional `callCount` fields for interaction verification.
69. **Release Tag Parsing Must Handle SemVer Pre-Release Suffixes**: Release automation scripts MUST support both stable (`vX.Y.Z`) and pre-release (`vX.Y.Z-rc.N`) tag patterns. The version calculation logic MUST correctly handle RC increment (develop merge: `rc.N` → `rc.N+1`) and stable promotion (main merge: strip `-rc.N` suffix). Unit test the parsing with edge cases before deploying pipeline changes.
70. **Docker Multi-Arch Build Stages Must Use `$BUILDPLATFORM`**: Intermediate compilation stages in multi-stage Dockerfiles (Gradle, Node, Go builds) MUST use `FROM --platform=$BUILDPLATFORM` to execute toolchains natively on the build host. Only the final runtime stage uses the target architecture. Omitting this causes ARM64 builds to run amd64 binaries under QEMU emulation, causing resolution failures or extreme slowness.
71. **GitHub Actions Version Pinning and Auditing**: All third-party GitHub Actions (e.g., `aquasecurity/trivy-action`, `docker/build-push-action`) MUST be pinned to a specific version tag, not `@latest` or `@main`. Pin versions MUST be audited periodically (quarterly or via Dependabot) to prevent API deprecation failures.
72. **Container Registry Push Steps Must Be Branch-Restricted**: Docker push and GitHub Release creation steps MUST include branch conditions (`if: github.ref == 'refs/heads/main' || github.ref == 'refs/heads/develop'`) to prevent permission errors when workflows run on feature branches. Apply least-privilege principles with explicit `permissions` blocks at the job level.
73. **Release Version State Machine for Branch Promotions**: Release automation MUST implement a clear version state machine: `develop` merge → auto-increment RC number (`vX.Y.Z-rc.N+1`); `main` merge → strip RC suffix for stable release (`vX.Y.Z`). Document expected version outputs for each branch merge scenario to prevent calculation mismatches.
74. **Pre-Release GitHub Releases Must Be Flagged**: Release creation logic MUST detect `-rc.N` suffix in tag names and set `prerelease: true` on the GitHub Release. The `:latest` container image tag MUST only be updated on stable releases (not RCs) to prevent users from accidentally pulling untested pre-release versions.
75. **Context Cancellation for External Process Execution**: Any function or collector executing external system binaries (e.g. `ping`) MUST use `exec.CommandContext(ctx, ...)` instead of `exec.Command(...)` to guarantee that child processes are immediately terminated when the context is cancelled or times out.

78. **Canvas-Based Interactive UIs Must Provide Accessible Alternatives**: Interactive `Canvas` components that handle pointer-only input (tap, drag, pinch) MUST provide a complementary accessible view (e.g., `LazyColumn` with `Modifier.semantics`) synchronized with the canvas data, enabling keyboard and screen-reader interaction. Overlay focusable invisible elements over interactive positions as an alternative.
79. **Production Compose Files Must Fail-Fast on Missing Secrets**: Production `docker-compose.yml` MUST use `${VAR:?error message}` (not `${VAR:-default}`) for all secret values (`POSTGRES_PASSWORD`, `INFRAMAP_MASTER_KEY`). This ensures `docker compose up` fails immediately when required secrets are missing, preventing deployment with known default credentials.
80. **CI/CD Checkout Must Disable Credential Persistence**: All `actions/checkout@v4` steps MUST set `persist-credentials: false`, especially in workflows that use the workspace as Docker build context (`COPY . ./`). Leaving `persist-credentials: true` writes `GITHUB_TOKEN` to `.git/config`, which gets copied into Docker image layers.
81. **Consistent Target CIDR Validation Across All Collectors**: All discovery collectors processing target CIDR strings MUST use shared CIDR validation (`ParseTargetPrefix`) to enforce maximum prefix size limits (max `/16`) uniformly across all protocols (ARP, ICMP, SNMP, Reverse DNS), preventing resource exhaustion when oversized targets (e.g. `/8`) are submitted.
82. **Loop Iteration Context Cancellation**: Loops processing entry slices in discovery collectors MUST check `if err := ctx.Err(); err != nil` at the start of each iteration to immediately halt processing and propagate context cancellation if the scan task is aborted.
83. **Format Specifiers in Test Assertion Format Strings**: Format specifiers in `t.Errorf` or `t.Fatalf` format strings MUST match the exact number and type of trailing arguments passed. Passing a literal instead of a variable argument (e.g. `t.Errorf("expected 8, got %d", 8)` when comparing against `got`) produces invalid format string warnings and hides assertion details.
84. **EventBus Publish Error Handling**: Calls to `eventbus.EventBus.Publish` MUST NOT discard returned errors via `_ = bus.Publish(...)`. Domain event publication failures MUST be checked and logged (e.g. `slog.Warn("failed to publish event", ...)`), ensuring observability and traceability when event dispatch fails due to backpressure or closed channels.
85. **Collector Error Isolation in Worker Pools**: Discovery engine orchestrators executing collectors concurrently MUST isolate worker errors using per-worker channels or error logging (`slog.Warn`). A failure in one collector (e.g., interface down or network error) MUST NOT fail or halt the entire scan cycle, allowing valid observations from remaining workers to process successfully.
86. **Paginated Repository Queries for Unbounded Result Sets**: Use-case methods that load all records from a repository (e.g. active inventory devices) MUST paginate using a loop with `pageSize`/`offset` and check `total` to aggregate all pages. Using a single large `LIMIT` (e.g. `10000`) risks missing records when the dataset exceeds the hardcoded limit. Repository errors MUST be propagated, not silently discarded.
87. **HTTP Endpoint Test Assertions Must Validate Response Body**: Controller and E2E integration tests that verify HTTP endpoint behavior MUST decode the response envelope and validate key domain fields (e.g. `cidr`, `total_collected`, `total_valid`) in addition to asserting the HTTP status code. Asserting only the status code allows regressions that remove or corrupt response fields to go undetected.
88. **Database Migrations Must Be Embedded and Auto-Applied on Startup**: Application containers MUST embed migration SQL files via `embed.FS` and execute `goose.UpContext()` during bootstrap (before pool creation). Migration failures MUST abort startup with a returned error — silently continuing leaves repositories operating on an incomplete schema while health reports "ok". Tests that don't need a database MUST omit `DatabaseURL` so the migration step is skipped.
89. **Application Version Must Be Injected at Build Time via ldflags**: The application version variable MUST be declared as `var` (not `const`) and injected via `-ldflags "-X pkg.AppVersion=${VERSION}"`. The Dockerfile MUST declare `ARG APP_VERSION=dev` and pass it to `go build`. CI workflows MUST forward the release tag as `build-args`. The Makefile MUST use `git describe --tags --exact-match` (not `--always`) so non-tagged commits report `dev` instead of a bare SHA.
90. **Compose Volume Paths Must Be Configurable via Environment Variable**: Production `docker-compose.yml` files MUST support an optional `${POSTGRES_DATA_PATH:-named-volume}` pattern allowing operators to override the default named volume with a host bind-mount path for external storage. Hardcoding host-specific paths in tracked compose files leaks infrastructure topology into version control.
91. **Compose DATABASE_URL Must Be a Standalone Variable**: Production `docker-compose.yml` MUST NOT interpolate `POSTGRES_PASSWORD` directly into `DATABASE_URL`. The raw password stored by PostgreSQL and the percent-encoded password in the connection URI are distinct values. `DATABASE_URL` MUST be received as its own env var so the operator controls encoding independently.
92. **All Tables with `updated_at` Must Have an UPDATE Trigger**: Every migration that creates a table with an `updated_at TIMESTAMPTZ` column MUST also create a `BEFORE UPDATE` trigger invoking the shared `update_updated_at_column()` function. The `-- +goose Down` section MUST drop the trigger before dropping the table. `DEFAULT NOW()` only applies on `INSERT`; without the trigger, `UPDATE` statements leave `updated_at` stale.
93. **Session Cookie Secure Flag Must Match Transport Protocol**: HTTP session cookies MUST set `Secure: true` only when the request arrives over TLS (`r.TLS != nil` or `X-Forwarded-Proto: https`). Hardcoding `Secure: true` causes browsers to silently reject the cookie on plain HTTP connections, breaking authentication for homelab and development deployments that run without TLS. The `X-Forwarded-Proto` header is trusted without a proxy allowlist because: (a) standard reverse proxies overwrite it, stripping client-injected values; (b) a client forging `https` on plain HTTP causes self-denial, not a security vulnerability; (c) direct TLS is checked first via `r.TLS`, short-circuiting the header check. See ADR-004.
94. **Session Cookie Secure Flag Test Matrix Must Cover All Transport Branches**: Tests for cookie-emitting endpoints (login, logout) MUST cover all three branches of transport detection: plain HTTP (`Secure: false`), `X-Forwarded-Proto: https` (`Secure: true`), and direct TLS via `r.TLS != nil` (`Secure: true`). Missing branch coverage allows regressions that silently break authentication for specific deployment topologies.
95. **Frontend API Paths Must Include Full Route Prefix**: All `ApiClient` call paths in repository implementations MUST include the full API route prefix (`/api/v1/...`). The `baseUrl` is set to `window.location.origin` (e.g., `http://host:8055`), and paths without the prefix (e.g., `/health` instead of `/api/v1/health`) resolve to SPA fallback routes that return HTML instead of JSON, causing silent deserialization failures that surface as `NetworkError`.
96. **WCAG AA Minimum Contrast for Custom Color Schemes**: All `on*` color tokens in custom `darkColorScheme` configurations MUST achieve a minimum WCAG AA contrast ratio of 4.5:1 against their paired surface token. Compute relative luminance per WCAG 2.1 formula and verify before committing. Specifically: `onSurfaceVariant` over `surfaceVariant`, `onError` over `error`, `onErrorContainer` over `errorContainer`.
97. **Dedicated `onError` Token for Dark Themes**: Dark color schemes MUST define a dedicated dark `onError` color with high contrast over the `error` surface, not reuse `onBackground`/`onSurface` (which are light text colors). Light foreground text (`#f8f8f2`) over a bright error surface (`#ff5555`) fails WCAG contrast. Use a near-black token (e.g., `#1a0a0a`).
98. **Inline Health Fallback Over Separate Fallback Jobs**: When a ViewModel fetches multiple concurrent API results and some are auth-gated while health is public, the error handler MUST extract health data inline from the already-awaited health result instead of launching a separate fallback job. Separate fallback jobs create race conditions with auto-refresh and SSE-triggered reloads, leading to out-of-order state updates.
99. **Generation Token for Stale Response Rejection**: ViewModels executing async fetch operations that can be re-triggered (manual refresh, SSE events, auto-refresh) MUST use a monotonic generation counter. Each trigger increments the counter; the async handler captures the generation at start and skips state updates if the generation has advanced (another fetch was triggered while this one was in-flight).
100. **Release Pipeline Must Use `pull_request: closed` Trigger for Auto-Merge Branches**: Workflows that must run after auto-merge (e.g., Release Pipeline creating RC tags) MUST trigger on `pull_request: types: [closed]` with `if: merged == true`, NOT on `push: branches:` to the target branch. `GITHUB_TOKEN` auto-merges suppress `push` events (#32). The `push:` trigger MUST only retain `tags:` patterns for manual tag pushes — branch entries MUST be removed since `pull_request: closed` already covers all branch merges. The checkout step MUST use `ref: ${{ github.event.pull_request.merge_commit_sha }}` to tag the actual merge commit (not the test merge ref). Git push credentials MUST use temporary scoped auth (`git -c http.extraHeader="Authorization: ..."`) instead of persisting tokens via `git remote set-url` (#80). Use a single global concurrency group (`release-pipeline`) to serialize all releases across branches. Restrict `workflow_dispatch` to protected branches (`develop`/`main`) via explicit `if` conditions.
101. **Kotlin/WASM Production Builds Must Disable Content-Hash on WASM Assets**: Webpack production builds content-hash asset filenames by default (e.g., `a92a356b.wasm`), but the Kotlin/WASM bootstrap and Skiko runtime load `.wasm` files by their original names (`inframap-frontend-wasm-js.wasm`, `skiko.wasm`) via hardcoded string paths. A `webpack.config.d/` rule MUST override the WASM asset filename to `[name][ext]`. Without this, the SPA fallback serves `index.html` (text/html) for the missing unhashed filenames, causing `WebAssembly.compile` to reject the incorrect MIME type.
102. **Stable-Named Assets Must Not Use Immutable Cache**: When unhashed WASM assets use stable filenames across releases (e.g., `skiko.wasm`), the SPA handler MUST NOT serve them with `Cache-Control: immutable`. Browsers would cache the old binary indefinitely and never revalidate, causing runtime incompatibility when the JS bundle updates but the WASM stays stale. Use `Cache-Control: public, no-cache` for `.wasm` files to force ETag/Last-Modified revalidation on every load. Reserve `max-age=31536000, immutable` for content-hashed assets only.
103. **SPA fs.Stat Error Classification**: When `fs.Stat` fails for a static asset path, the SPA handler MUST check `errors.Is(err, fs.ErrNotExist)` and return 404 only for that case. Permission errors or I/O failures MUST return 500 (`http.StatusInternalServerError`). Blindly returning 404 for all stat errors masks filesystem corruption or misconfigured embed directives.
104. **Shutdown Status Must Be Distinct from Error**: Background services cancelled by graceful shutdown MUST set persisted status to `"cancelled"`, not `"error"`. Shutdown is controlled interruption, not failure. Monitoring and alerting MUST NOT trigger on `cancelled` status. On boot, stale `running` or `cancelled` statuses MUST be reset to `idle` with a structured warning log. See ADR-005.
105. **Scheduler Reconciliation Loop for Event-Driven State**: Background schedulers reacting to domain events via EventBus MUST implement a periodic reconciliation loop (e.g. every 5 min) that diffs desired state (database) against actual state (registered jobs). This guarantees eventual consistency independent of event bus reliability (dropped events, buffer full, implementation changes).
106. **Shared Maps Require Dedicated Mutex**: Every Go `map` accessed from multiple goroutines MUST have a dedicated `sync.Mutex`. When two map operations must be atomic (e.g., unregister + register), they MUST be performed under the same lock acquisition. This applies to all internal state maps, not just those obviously concurrent.
107. **SQL Migrations: NOT VALID + VALIDATE for CHECK Constraints**: `ADD CONSTRAINT ... CHECK (...)` MUST use `NOT VALID` to avoid full-table scans and write locks. Existing violating rows MUST be normalized first. A separate `VALIDATE CONSTRAINT` step confirms the constraint after normalization.
108. **Migrations in Embedded Directory Only**: SQL migrations MUST be placed in the directory embedded by `//go:embed` in `migrate.go` (`internal/platform/db/migrations/`). Migrations in other directories are silently ignored.
109. **Background Service Context Independence**: Background services (scheduler, workers) MUST own their own `context.Context` derived from `context.Background()`, cancelled only in `App.Close()`. They MUST NOT receive the signal context — that would cancel in-flight work before HTTP shutdown completes.

133. **Mandatory Browser E2E Quality Gate for WASM SPA**: All frontend changes and single-binary packaging MUST be validated through the Playwright browser E2E test suite in `tests/e2e-browser/`. 134. **Compose WASM Dynamic Viewport Management & Null-Tolerant Collections**: In Compose Multiplatform WASM, applications MUST use `ComposeViewport(document.body!)` rather than deprecated `CanvasBasedWindow` to ensure Skiko canvas automatically resizes with dynamic browser viewports and DevTools dock/undock events without leaving blank bands. 136. **Compose WASM Binary Resource Serving & JS Window Binding**: In the Go backend SPA file server (`internal/platform/spa`), all Compose Multiplatform binary resource assets (`composeResources/**`, `.cvr`, `.bin`, `.dat`) MUST be explicitly categorized as static assets (`isStaticAsset`), served with `Content-Type: application/octet-stream`, and return HTTP 404 on missing assets rather than falling back to `index.html`. 137. **Topology Graph DTO Schema Alignment & Empty State Resilience**: In Kotlin Multiplatform DTOs mapping graph structures (`TopologyGraphDto`, `TopologyNodeDto`, `TopologyEdgeDto`), field names MUST align with backend JSON schemas (`hostname` for node label, `source_device_id` and `target_device_id` for edge vertices). 138. **Automated Client Storage/Cache Purge & Pre-Boot Version Invalidation**: To prevent stale IndexedDB compiled WASM modules, obsolete Cache Storage entries (`window.caches`), corrupted LocalStorage schemas, or lingering Service Workers from freezing regular browser tabs on version upgrades (especially in plain HTTP homelab environments where `Clear-Site-Data` is discarded by browsers), `index.html` MUST execute an asynchronous pre-boot IIFE. 139. **Strict API-Scoped Fetch Interception for WASM Resource Safety**: In Kotlin Multiplatform WASM applications wrapping `window.fetch` (e.g. for automatic cookie/credentials dispatch), the fetch interceptor MUST strictly inspect the target URL and only apply modifications (such as injecting `credentials: 'same-origin'`) if the request URL explicitly targets backend API routes (`url.indexOf('/api/') !== -1`). 179. **Pin the Linter to One Version, Built From Source**: `golangci-lint` MUST be pinned to the same version in `Makefile` and `.github/workflows/ci.yml`, and MUST be built from source (`go run ...@<version>` locally, `install-mode: goinstall` in CI) rather than resolved to a published release binary. 180. **A Failing Local Gate Is Not Always a Failing Codebase**: `make lint` builds the linter from the module proxy, so a DNS or proxy outage fails the target with `dial tcp: lookup proxy.golang.org: no such host` and the pre-push hook reports it as a lint failure. 181. **Repository-Event Workflows Only Run From the Default Branch**: GitHub resolves workflows differently per trigger. A `pull_request` workflow is read from the PR's **base** branch, which is why `auto-merge.yml` and `pr-target-check.yml` work while living only on `develop`. But `issue_comment`, `schedule`, `workflow_dispatch` and other repository-level events are always resolved from the **default branch** (`main` here). `coderabbit_rate_limit_handler.yml` triggers on `issue_comment` and exists only on `develop`, so it has never executed once — the auto-retry it promises is inert, and `gh run list --workflow=<file>` returns HTTP 404 "not found on the default branch", which is the fastest way to detect this. Any workflow reacting to comments, schedules or manual dispatch MUST be merged to the default branch before it does anything at all; keeping it only on `develop` produces a file that reads as protection and provides none.

182. **Gitleaks Scans Commit History, So Suppression Must Live in the Introducing Commit**: `.gitleaksignore` entries have the form `<commit-sha>:<path>:<rule>:<line>` and are bound to one commit, so any rebase, squash-merge or amend rewrites that SHA and the suppression silently stops applying — guaranteed on stacked PRs, where every branch is rebased each time the one below it merges. Use an inline `//gitleaks:allow` comment instead: it travels with the content and survives history rewrites. Crucially, the scan walks every commit in the PR range, not just the final tree, so adding the suppression in a *later* commit does not clear the finding — the earlier commit still carries the unsuppressed value and the job still fails, reporting a `Commit:` SHA that is not the branch head. The suppression MUST be present in the commit that introduces the value, which on an existing branch means amending or collapsing history rather than appending a fix. Reserve `.gitleaksignore` for findings already immutable in the default branch.

183. **Never Rebuild a URL by String Concatenation After Validating It**: Provider transports take an endpoint from operator configuration, so the value is attacker-influenced from a static-analysis standpoint. Adjusting its scheme with string surgery — `"https://" + strings.TrimPrefix(raw, "tcp://")` — drops the validated, structured `*url.URL` back into an unstructured string, which both defeats CodeQL's taint tracking (`go/ssrf`, "Uncontrolled data used in network request", raised as **critical** and merge-blocking) and risks a string that reparses into a different host than the one that was checked. Parse first, adjust `Scheme` on the parsed value, validate the host, and rebuild the `url.URL` from those validated parts only. Host validation MUST reject empty hosts, embedded credentials (`@`), path separators, and whitespace or control characters that could split a request line. Note that a `// lgtm[go/ssrf]` comment suppresses nothing: LGTM was retired and CodeQL does not honour it.

184. **A Configured Endpoint Must Never Fall Back to a Local Default**: When an operator explicitly configures a provider endpoint, an unrecognized value MUST be an error, never a fallback to a default transport. The Docker provider routed any `tcp_url` that did not start with `http://`, `https://` or `tcp://` to the local Unix socket, so a typo such as `htp://host:2376` silently connected to the machine's own daemon — health-checking green and ingesting the InfraMap host's own containers as if they belonged to the remote host. A wrong endpoint must fail loudly; falling back turns a typo into silent, plausible-looking wrong data.

185. **A Test That Asserts Failure Must Not Depend on a Service Being Absent**: This also applies to fixtures that leave a transport unconfigured. A provider collector given an empty config falls back to its default transport — for Docker, the local daemon socket — so a discovery test asserting "every collector errored" quietly depends on the machine having no Docker installed. Point such fixtures at a deterministically unreachable endpoint (a closed port such as `tcp://127.0.0.1:1`, which needs no DNS) instead of relying on a default that resolves differently per machine. Original finding: The bug above passed every local run and only failed in CI, because GitHub runners have Docker installed and `/var/run/docker.sock` available while the development machine did not. The suite asserted "invalid config returns an error" and got one locally for the wrong reason — the fallback socket was simply unreachable. When a test asserts that something is rejected, assert on *why*: match the expected validation error rather than merely `err != nil`, so the test cannot pass because an unrelated dependency happened to be missing. The same asymmetry explains failures far from the change, such as a discovery scan expected to be all-error succeeding because one collector reached a daemon that only exists on the runner.

186. **Accepting a By-Design Finding Is a Documented Decision, Not a Silenced Check**: CodeQL's `go/request-forgery` flags every request whose URL derives from external configuration. For provider transports that flow *is* the feature — the operator supplies the daemon address — so no amount of restructuring removes the alert without removing the capability. Such a finding is dismissed per alert with reason "won't fix" and a written rationale, never by excluding the query for a whole directory: a path filter would also silence genuine findings in code that does not exist yet, whereas a per-alert dismissal keeps every new occurrence visible. The dismissal is only legitimate once the mitigations are real and testable — here: parse once and adjust the scheme on the parsed value (#183), validate the host against empty values, embedded credentials, path separators and control characters, rebuild the URL from validated parts only, reject unsupported schemes instead of falling back (#184), and verify TLS by default (#174). Record the decision, the alert numbers and the mitigations in the ADR/RFC so the next reader finds the reasoning rather than an unexplained green check. The GitHub API caps `dismissed_comment` at 280 characters, so the comment points at the documentation rather than carrying the argument.

187. **Identity Must Be Persisted on the Update Path, Not Only on Creation**: A canonical identity written only when a device is first created never reaches devices that already exist. The Matcher's Tier 0 reads `metadata->>'provider_ref'`, but the reconciler merged incoming payload under a per-source namespace (`meta[sourceType]`), so a device first discovered by a network sweep and later matched by MAC to a provider observation was updated without ever gaining a `provider_ref`. Tier 0 then could not match it on any subsequent run, and the moment the workload lost its address — a container stopping — it was recreated as a duplicate: precisely the churn Tier 0 exists to prevent. Whenever an attribute is the key some later lookup depends on, write it in the reconciler as well as the creator, and mark the record changed so the write is actually persisted.

188. **Land the Rationale Before Unblocking the Merge**: Dismissing a blocking security alert, approving a review or otherwise clearing the last gate can complete a merge within seconds — auto-merge fires as soon as the branch becomes mergeable. A rationale written after that moment has nowhere to land: the PR is already closed. On a stacked branch it is then easy to lose the commit entirely, because the follow-up is sitting as the branch tip and that tip is exactly what gets passed as `<old-base>` to the next `git rebase --onto <new-base> <old-base> <branch>` — which replays the commits *after* `<old-base>` and excludes `<old-base>` itself. (The command does not drop later commits; it drops the one you named.) The result is that the decision reaches the repository while its reasoning never does, leaving an unexplained dismissal for the next reader. Commit and push the rationale first, confirm it is on the branch the PR will merge, and only then remove the block. When a merge does slip ahead of the documentation, recover it as its own PR rather than leaving the gap.

189. **Provider Transports Must Not Follow Redirects**: `http.Client` follows up to ten redirects by default and strips credentials only when the destination is neither the same domain nor a subdomain of the original. That is too permissive for a transport carrying provider credentials: a Proxmox API token travels to any subdomain of the configured host, and a TLS client certificate is worse still, because it lives on the `Transport` and is therefore presented to every redirect destination regardless of domain — the header-stripping rule never applies to it. A management API has no legitimate reason to redirect, so provider clients MUST set `CheckRedirect` to refuse (returning `http.ErrUseLastResponse`), letting the caller treat the non-200 status as a failure. Each provider package MUST carry a test that redirects to a second server and asserts both that the health check fails and that the redirect target received no credentials. In that test the redirect target MUST be a constant: deriving it from the incoming request (`attacker.URL+r.URL.Path`) is an open redirect and Semgrep blocks on it — `go.lang.security.injection.open-redirect` does not care that the handler is a stub, and the stub does not need the path anyway.

190. **A Lookup Table Keyed on Values Nothing Produces Is Dead Code That Looks Alive**: The topology canvas mapped link types to edge colours with a `when` over `"physical"`, `"virtual"`, `"container"` and `"routed"`, while the backend emits `layer2_physical`, `virtual_hypervisor`, `container_veth` and `layer3_routed`. Whenever a UI branches on a value that originates in another layer, the accepted values MUST be asserted against the ones that layer actually produces, in a test that fails if either side is renamed. A default branch is for genuinely unknown values, never the branch everything lands on.

191. **A UI Control Must Not Exist Before the Behaviour Behind It**: ADR-013 section 2 stated that collector configs could reference a stored credential instead of carrying secrets inline, but `ResolveCollectorConfig` only ever decrypted the collector's own config — the reference was never resolved. Building the field in the form alone would have produced a control that looks like it works: the plan saves, the run starts, and the provider fails to authenticate with an error that points nowhere near the cause. Before adding an input for a documented capability, verify the capability exists end to end; an ADR describing a decision is not evidence that the decision was implemented. When the reference cannot be resolved the run now fails loudly with the credential id in the message, because continuing with no credentials would surface as an authentication failure and send the operator looking in the wrong place.

192. **A Credential Says Who, Never Where**: A stored credential holds authentication, not the endpoint it authenticates against. Treating a credential reference as "the provider is now fully configured" and hiding the address fields leaves a Proxmox collector with no `api_url` and a Docker collector with neither socket path nor TCP URL — and the latter then falls back to the machine's own daemon socket, reintroducing the failure of guideline #184 through a different door. A credential waives only the fields it actually supplies: the secrets. Endpoint validation stays active regardless.

193. **Overriding Values Must Be Cleared When Their Source Is Replaced**: Collector-level settings take precedence over a referenced credential's, which is what lets one credential back several plans with a per-plan override. That precedence turns into a trap the moment the operator types a token and *then* picks a credential: the typed value stays in the config, outranks the credential, and the run authenticates with the secret the operator thought they had replaced. Whenever one input supersedes another, selecting it MUST clear the values it supersedes — a precedence rule is only safe if the losing values are actually removed.

194. **A Merge Performed With GITHUB_TOKEN Triggers Nothing Downstream**: GitHub suppresses workflow runs for events originated by `GITHUB_TOKEN`, so a pull request merged by a workflow — `auto-merge.yml` arming auto-merge with `github.token` — closes as `github-actions[bot]` and its `pull_request: closed` event starts no other workflow. `release.yml` triggers on exactly that event, so every auto-merged PR of an entire epic landed on `develop` without producing a release candidate, silently: nine merges, one release run, and that one only because the PR happened to be merged by hand. The symptom is invisible from the PR, which shows all checks green. Diagnose it by comparing `mergedBy` across PRs (`gh pr view <n> --json mergedBy`): an `app/github-actions` merge is one whose downstream automation did not run. Automation that must trigger further automation has to authenticate as a real account through a PAT, or be started explicitly with `workflow_dispatch`, which is exempt from the suppression.

195. **A Green CodeRabbit Check Is Not Evidence That a Review Happened**: CodeRabbit stops reviewing automatically once a repository falls under its OSS threshold — "This repository does not receive automatic reviews because it has fewer than 10 stars" — and it announces this by posting a *skip* comment whose status check still reports **SUCCESS**. Nothing fails, nothing is red, and `auto_review.enabled: true` in `.coderabbit.yaml` stays exactly as written, because the platform policy overrides repository configuration rather than erroring on it. The result is a PR that satisfies every gate and merges with no review at all: here the switch landed silently between #181 and #182, and #182 was auto-merged unreviewed within the hour. Detect it by reading the body of CodeRabbit's own comment, never its check conclusion and never the inline-comment count: `pulls/<n>/comments` is zero both when no review ran *and* when a review ran and found nothing, so the count cannot tell the two apart. The reliable signal is in `gh api repos/<owner>/<repo>/issues/<n>/comments` — a body carrying `fewer than 10 stars` means skipped, `Review limit reached` means rate-limited, and a review that actually ran leaves either a `walkthrough_start` block (the first review of a PR) or a `recent_review_start` one (every review after it) — the two markers are not interchangeable, and matching only one of them reports a reviewed PR as unreviewed. Read the comment by `updated_at`, never `created_at`: CodeRabbit **edits its existing summary comment** in place on each review, and will even overwrite a rate-limit warning with the eventual review, so a reviewed PR can show a creation timestamp from hours earlier and no new comment at all. Which revision was covered is stated inside that body and nowhere else — as `Reviewing files that changed ... between <base> and <head>` on an incremental pass, or as `**Merge Risk:** ... up to <short-sha>` on a first one. Both forms need care before they can be compared with `headRefOid`. The `Merge Risk` form is abbreviated — `up to 1c7b4` against a 40-character `headRefOid` — so compare by prefix (`headRefOid.startsWith(short)`) rather than for equality, which never matches. The incremental form names two commits, and only the second one matters: the review covers up to `<head>`, so comparing the `<base>` end reports a current review as stale. Getting either wrong defeats the purpose, because this comparison is the only way to tell a review of the current head from a review of a commit some rebase has since replaced. An empty `pulls/<n>/comments` then means clean, not absent. Recover a single PR by commenting `@coderabbitai review`, which works because the request comes from a real account; a workflow posting the same command with `GITHUB_TOKEN` cannot substitute for it, both because CodeRabbit ignores commands from bots and because of the event suppression in #194. Any process that treats a CodeRabbit review as a quality gate MUST verify that a review body exists before merging, since the absence of one is indistinguishable from success at the check level.

196. **Auto-Merge Armed at Open Turns a Manual Review Request Into a Race**: `auto-merge.yml` arms auto-merge the moment a PR opens, so the PR merges the instant the required checks go green — which, when CodeRabbit has skipped the review (#195), is a state reached with no review at all. Requesting one afterwards with `@coderabbitai review` does not recover it: here the command was posted on #183 at 18:44, the PR auto-merged at 18:55:58, and CodeRabbit replied at 18:58:06 with "Action not completed — Pull request is closed." The review lost the race by two minutes and the change reached `develop` unreviewed. Compounding it, the OSS tier grants roughly one review per hour ("Next included review available in 59 minutes"), so firing the command at three parallel PRs consumes the quota on the first and rate-limits the rest — parallel streams cannot all be reviewed in the same window. When reviews are not automatic, auto-merge MUST be disabled on open PRs (`gh pr merge <n> --disable-auto`) until a review body actually exists, and the request MUST be staggered across PRs rather than issued to all of them at once. Verify the arming with `gh pr view <n> --json autoMergeRequest`, and the review with the comment body — never with the inline count, which is zero for a clean review exactly as it is for no review at all (#195). A PR is safe to merge only once a CodeRabbit-authored summary carries a review marker whose stated revision matches the current head.

200. **Two Triggers for the Same Merge Publish Two Releases**: `release.yml` listened on both `push: branches [develop, main]` and `pull_request: closed`, and a merge into `develop` satisfies both. GitHub starts one run per matching trigger, so semantic-release executed twice on the same commit: the merge of #184 produced two complete, separately published releases — `v1.0.0-rc.76` and `v1.0.0-rc.77` — both built from the identical SHA `9dcdb27`, with the second one now sitting as "latest". `concurrency` with `cancel-in-progress: false` makes this worse rather than better — it serialises the runs so the second one starts cleanly after the first has already tagged, instead of colliding visibly. The symptom is version inflation and indistinguishable duplicate artifacts — nothing marks either release as the spurious one, and `latest` points at whichever run finished second (an earlier `v1.0.0-rc.74` was the same mechanism, misattributed at the time), and it hides until the first merge performed by a real account, because a `GITHUB_TOKEN` merge suppresses *both* triggers equally (#194) and produces zero runs. That is also why adding `pull_request: closed` did not fix the missing-release problem it was added for: the redundant trigger is invisible in the failing case and harmful in the working one. A release pipeline MUST have exactly one path per event — `push` on the release branches, plus `workflow_dispatch` for the cases automation cannot reach — and the fix for a bot merge is a PAT, never a second trigger.
